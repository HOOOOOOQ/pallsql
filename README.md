# PALLSQL

**PALLSQL — Offline mobile web development environment built with Flutter for Android.**

An early Android-first MVP for managing a local website workspace. The application stores files and SQLite data in Android app-private storage; it does not require root or Termux.

## Implemented

- Dark Material 3 dashboard and Home / Servers / Database / Files / Settings navigation.
- App-private `PALLSQL/` workspace with `htdocs/`, `projects/`, `database/`, `backups/`, `logs/`, `config/` and `tmp/` directories.
- Real Dart HTTP server serving static content on `127.0.0.1:8080` (configurable) with index handling, 404 responses and traversal checks. The listener exists while the app process is alive; Android does not guarantee background longevity.
- Real local SQLite database using `sqflite`; the SQL page runs statements against `database/default.db` and displays result rows/errors.
- Basic document-root file listing, create and edit; in-memory runtime logs.
- Android CI and tag-triggered release workflows.

## Not implemented (do not assume support)

PHP runtime and PHP execution are **unavailable**; `.php` is not interpreted. MariaDB/MySQL is **not included** (SQLite is not a substitute). The editor is a basic text editor, not a syntax-highlighting IDE. Project ZIP import/export, backup/restore, terminal, complete file operations, SQL import/export and foreground service are not complete. LAN serving is intentionally not enabled. The app is not yet validated for Play Store distribution.

## Development requirements

- Flutter stable (Dart constraint `>=3.3.0 <4.0.0`), Android SDK and Java 17 for Android builds.
- This execution environment did not have Flutter, Dart, Java or Gradle installed, so local analyzer/tests/APK build could not be run here.

```sh
flutter pub get
 dart format lib test
flutter analyze
flutter test
flutter build apk --debug
flutter build apk --release
```

The Android host project is generated by `flutter create --platforms=android --org com.pallsql --project-name mobile .` if needed. This sets application ID `com.pallsql.mobile`. Review generated Android manifest/network policy before distributing: serving is loopback-only and Android cleartext traffic may need an explicit policy for browser access.

## CI/CD

`.github/workflows/android.yml` checks formatting, analyzer, tests and debug/release builds on main pushes, PRs to main and manual dispatch, then uploads APKs for 14 days as `PALLSQL-Android-APK`. The tag workflow runs checks/build and attaches an unsigned release APK to a GitHub Release. No signing key is included; configure a developer-owned keystore through GitHub Secrets before distributing signed updates. Releases require `vX.Y.Z` tags.

## Runtime and security notes

- The web server binds only to IPv4 loopback, avoiding LAN exposure by default.
- Static document root is the workspace `htdocs`. Traversal outside it is rejected; test URL-encoded and platform-specific paths on target Android devices before production use.
- The server runs in the app process. Android may stop the process in the background; a correctly permissioned foreground service is future work.
- PHP Android runtime selection/packaging and MariaDB native ABI, dependencies, initialization, licensing and persistence have not been verified; neither is claimed as supported.
- SQLite database is stored locally and works offline. Avoid placing secrets in project files or logs.
